# Agent log (scratch — not part of the submission, becomes AGENT_USAGE.md source material)

Format per entry: what happened, what was wrong, why, what I did instead.

## Module 1 — Bootstrap
- create-next-app refused to scaffold directly into `/Volumes/Projects/Aggroso` because
  the directory name "Aggroso" contains a capital letter and npm package names must be
  lowercase. Worked around by scaffolding into a temp dir with a valid name
  (`nutrition-planner`) and moving the files into place, keeping `package.json`'s
  `name` field as `nutrition-planner`.
- create-next-app's default installed Next.js 16.2.12, but the spec locks the stack to
  Next.js 15. Pinned `next` and `eslint-config-next` to `15.5.22` explicitly after
  scaffolding rather than letting the default install stand.

## Module 3 — Nutrition knowledge base
- The spec requires nutrition numbers to be retrieved from a documented source, never
  invented — including by me. So instead of writing the seed CSV from memory, I fetched
  real values from the USDA FoodData Central `/v1/foods/search` API and built the CSV
  programmatically from the JSON responses (fdcId kept as `source_id` for traceability).
- USDA's DEMO_KEY has a very low rate limit (10 req/hour observed), which wasn't enough
  to cover ~90 distinct common foods via search. The user supplied a real personal FDC
  API key mid-task (3600 req/hour) which unblocked fetching the remaining gaps (plain
  milk, rice, oats, salmon, tuna, sweet potato, lettuce, peppers, nuts, etc). The key is
  only used for this one-time offline seed-generation step — it is not used by the
  running app and was not written to any file in the repo or to .env.example.
- USDA's search endpoint doesn't return standard "1 egg = 50g" style serving/measure
  data, only per-100g proximates. Rather than inventing per-piece gram weights, the
  seed stores everything per 100g and documents this as a known limitation in
  data/README.md — the app will ask the user for a gram quantity instead of guessing.

## Module 4 — AI extraction layer
- The spec named `gemini-2.5-flash` via `@google/generative-ai`. Checked both before
  writing any code: `@google/generative-ai` hasn't published since April 2025 (dead),
  and `gemini-2.5-flash` returns a live 404 "no longer available to new users" against
  the actual API key. Switched to `@google/genai` (actively maintained, last published
  days ago) and `gemini-flash-latest` (Google's maintained alias, currently resolving
  to gemini-3.6-flash). Documented as a substitution in CLAUDE.md rather than silently
  changing the locked stack.
- That resolved model has "thinking" on by default and burned ~600 reasoning tokens on
  a two-word reply in a first test. Set `thinkingConfig.thinkingLevel: MINIMAL` for the
  extraction call — same output quality in a live smoke test, no thinking-token cost.
  (`thinkingBudget: 0`, the older Gemini 2.5 knob, returned 400 INVALID_ARGUMENT on this
  model — the newer models use `thinkingLevel` instead.)
- Ran a live smoke test (not part of the committed test suite) against the real API
  before trusting the design: confirmed the model returns zero calorie/macro numbers,
  correctly raises clarification questions for missing quantity/preparation, and Zod-
  validates cleanly against the JSON Schema generated by `z.toJSONSchema()`.

## Module 5 — Calculation engine
- Caught my own mistake while writing calculate.ts's tests: the curated seed CSV had
  no chicken entry at all — dropped during an earlier curation pass despite chicken
  being one of the most common things a meal-logging demo would need. Test fixtures
  had drifted to plausible-but-made-up numbers (119 kcal/21.2g protein) instead of
  citing something real, which is exactly the failure mode this whole assignment is
  about avoiding. Fetched the real USDA record ("Chicken, broilers or fryers, breast,
  meat only, cooked, roasted", fdcId 171477: 165 kcal/31g protein/0g carbs/3.57g fat
  per 100g), added it as the seed CSV's 88th row, and rewrote the test fixtures to
  match it exactly instead of leaving invented numbers in the test suite.
